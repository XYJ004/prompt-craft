# 🏗️ 系统设计提示词

## 🎯 适用场景

- 系统架构设计
- 技术方案评审
- 架构文档编写
- 技术选型讨论

---

## 💡 基础版提示词

```
请帮我设计一个系统架构。

## 需求
- 功能：[描述核心功能]
- 用户量：[预期用户规模]
- 性能要求：[响应时间、并发量]

请提供：
1. 整体架构图描述
2. 技术栈建议
3. 数据库设计
4. 关键技术点
```

---

## 💡 进阶版提示词（推荐）

```
你是一位拥有 15 年经验的系统架构师，曾在阿里、字节等大厂负责核心系统设计。请为以下需求设计完整的技术方案。

## 业务背景
- 业务领域：[如 电商/金融/社交/IoT]
- 核心功能：[主要功能点]
- 目标用户：[用户群体]
- 商业模式：[盈利模式]

## 非功能需求
- 用户规模：[如 日活 100 万]
- 并发量：[如 峰值 1 万 QPS]
- 数据量：[如 日增 1 亿条]
- 响应时间：[如 P99 < 200ms]
- 可用性：[如 99.99%]
- 数据一致性：[如 强一致/最终一致]

## 技术约束
- 团队规模：[如 20 人]
- 技术栈偏好：[如 Java/Go/Node]
- 部署环境：[如 阿里云/K8s]
- 预算范围：[如 月 50 万]

## 设计要求

### 1. 整体架构
- 架构风格选择（微服务/单体/Serverless）
- 服务拆分策略
- 通信方式选择
- 数据流向图

### 2. 技术选型
- 前端技术栈
- 后端技术栈
- 数据库选型
- 中间件选型
- 运维工具

### 3. 数据设计
- 数据库选型与分库分表
- 缓存策略
- 消息队列
- 数据一致性方案

### 4. 高可用设计
- 容灾方案
- 限流降级
- 熔断机制
- 灰度发布

### 5. 安全设计
- 认证授权
- 数据加密
- 安全防护
- 审计日志

### 6. 性能优化
- 缓存策略
- 数据库优化
- 异步处理
- CDN 加速

|------|----------|----------|----------|

| 后端 | Go | 高并发 | Java |

### 三、核心设计

#### 3.1 服务拆分
[服务列表和职责]

[核心表结构]

#### 3.3 缓存设计
[缓存策略]

#### 3.4 消息队列
[异步处理流程]

### 四、高可用方案
[容灾、降级、熔断]

### 五、安全方案
[认证、加密、防护]

### 六、成本估算
[服务器、带宽、人力]

### 七、风险与应对
[技术风险和应对措施]
```

## 🌟 效果展示

**输入：**
```
设计一个短视频系统
- 日活：1000万
- 并发：10万 QPS
- 存储：日增 100TB
```

**输出：**
```
### 一、架构概览

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   客户端    │────▶│   CDN/WAF   │────▶│  API 网关   │
└─────────────┘     └─────────────┘     └─────────────┘
                                               │
                    ┌──────────────────────────┼──────────────────────────┐
                    ▼                          ▼                          ▼
            ┌─────────────┐            ┌─────────────┐            ┌─────────────┐
            │  视频服务   │            │  用户服务   │            │  推荐服务   │
            └─────────────┘            └─────────────┘            └─────────────┘
                    │                          │                          │
                    ▼                          ▼                          ▼
            ┌─────────────┐            ┌─────────────┐            ┌─────────────┐
            │ 对象存储OSS │            │  MySQL集群  │            │ Redis集群   │
            └─────────────┘            └─────────────┘            └─────────────┘
```

### 二、技术选型表

| 层级 | 技术选择 | 选型理由 |
|------|----------|----------|
| CDN | 阿里云 CDN | 国内节点多，带宽成本低 |
| API 网关 | Kong | 高性能，插件丰富 |
| 视频处理 | FFmpeg + GPU | 编转码效率高 |
| 对象存储 | 阿里云 OSS | 海量存储，自动冗余 |
| 数据库 | TiDB | 水平扩展，MySQL 兼容 |
| 缓存 | Redis Cluster | 高可用，支持集群 |
| 消息队列 | Kafka | 高吞吐，持久化 |
| 推荐 | Flink + TensorFlow | 实时计算 + ML |

### 三、核心设计

#### 3.1 视频上传流程
1. 客户端请求上传凭证
2. 直传 OSS（断点续传）
3. 触发转码任务
4. 生成多清晰度版本
5. 更新元数据

#### 3.2 推荐算法
- 冷启动：热门 + 标签匹配
- 个性化：协同过滤 + 深度学习
- 实时更新：Flink 实时特征

### 四、高可用方案

| 方案 | 措施 |
|------|------|
| 容灾 | 多机房部署，异地多活 |
| 限流 | 令牌桶 + 熔断 |
| 降级 | 关闭非核心功能 |
| 灰度 | 按用户 ID 分流 |

### 五、成本估算

| 项目 | 月成本 |
|------|--------|
| CDN 带宽 | ¥50万 |
| OSS 存储 | ¥30万 |
| 计算资源 | ¥40万 |
| **合计** | **¥120万/月** |
```
