# 🔍 代码审查提示词

## 🎯 适用场景

- Pull Request 审查
- 代码质量检查
- 团队代码评审
- 个人代码优化

---

## 💡 基础版提示词

```
你是一位资深代码审查专家，拥有 15 年以上的软件开发经验。请审查以下代码：

代码语言：[填写语言，如 JavaScript/Python/Go/Java]
代码内容：
```
[粘贴你的代码]
```

请从以下维度进行审查：

1. **潜在 Bug** - 是否有逻辑错误、边界情况未处理
2. **性能问题** - 是否有性能瓶颈、资源泄漏
3. **安全问题** - 是否有注入漏洞、敏感信息暴露
4. **代码规范** - 是否符合最佳实践、命名规范
5. **可维护性** - 代码是否易于理解和修改

请用中文回复，格式如下：
- 🔴 严重问题（必须修复）
- 🟡 建议改进（可选优化）
- 🟢 做得好的地方
```

---

## 💡 进阶版提示词（推荐）

```
你是一位顶级科技公司的 Staff Engineer，专注于代码质量与最佳实践。请对以下代码进行全面审查：

## 代码信息
- 语言/框架：[如 React + TypeScript]
- 代码位置：[如 src/components/UserList.tsx]
- 业务背景：[如 用户列表组件，支持分页和搜索]

## 待审查代码
```
[粘贴你的代码]
```

## 审查要求

### 第一层：功能正确性
- 是否实现了预期功能？
- 边界情况是否处理？
- 错误处理是否完善？

### 第二层：代码质量
- 是否遵循 SOLID 原则？
- 是否有代码重复？
- 命名是否清晰？
- 注释是否充分？

### 第三层：性能考量
- 时间复杂度是否最优？
- 是否有不必要的渲染/计算？
- 资源是否正确释放？

### 第四层：安全性
- 是否有注入风险？
- 敏感数据是否加密？
- 权限检查是否完整？

### 第五层：可测试性
- 是否容易编写单元测试？
- 依赖是否可 Mock？

## 输出格式

请按以下格式输出审查结果：

### 🛑 必须修复
| 行号 | 问题类型 | 问题描述 | 修复建议 |
|------|----------|----------|----------|
| 42 | 安全 | SQL 注入风险 | 使用参数化查询 |

### ⚠️ 建议改进
| 行号 | 问题类型 | 问题描述 | 改进建议 |
|------|----------|----------|----------|
| 15 | 性能 | 循环内有重复计算 | 提取到循环外部 |

### ✅ 做得好的地方
- 使用了 TypeScript 类型保护
- 错误边界处理完善

### 📝 总体评价
[给出整体代码质量评分和改进建议]
```

## 📝 使用说明

1. 选择适合的版本（基础/进阶/轻量）
2. 复制提示词
3. 替换占位符（语言、代码、背景）
4. 发送给 AI（Claude/GPT/Copilot）

---

## 🌟 效果展示

**输入：**
```javascript
function getUser(id) {
  return db.query(`SELECT * FROM users WHERE id = ${id}`);
}
```

**输出：**
```
### 🛑 必须修复
| 行号 | 问题类型 | 问题描述 | 修复建议 |
|------|----------|----------|----------|
| 2 | 安全 | SQL 注入风险：直接拼接用户输入 | 使用参数化查询 |

修复示例：
```javascript
function getUser(id) {
  return db.query('SELECT * FROM users WHERE id = ?', [id]);
}
```

### ⚠️ 建议改进
| 行号 | 问题类型 | 问题描述 | 改进建议 |
|------|----------|----------|----------|
| 2 | 类型 | 返回类型未定义 | 添加 TypeScript 类型注解 |

### ✅ 做得好的地方
- 函数命名清晰
- 单一职责原则
```

---

## ⚠️ 注意事项

- 大文件建议分段审查
- 审查结果仅供参考，人工确认
- 不同 AI 模型效果可能有差异
- 敏感代码注意脱敏
